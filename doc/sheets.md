## SH1106 OLED 状态显示

屏幕为 1.3 寸、128×64、7 针 SH1106 模块，使用 **4 线 SPI** 模式。

| OLED 引脚 | ESP32-S3 引脚 | 用途 |
| --- | --- | --- |
| GND | GND | 共地 |
| VCC | 3V3 | 电源 |
| D0 / SCL | GPIO12 | SPI 时钟 |
| D1 / SDA | GPIO11 | SPI MOSI |
| RES / RST | GPIO46 | 低电平复位 |
| DC / D-C | GPIO9 | 命令／数据选择 |
| CS | GPIO10 | 片选 |

保持模块为 4 线 SPI 模式，CS 接 GPIO10。资料包包含 0.96 寸 SSD1306 示例；当前固件按 SH1106 初始化，以 8 页、每页 128 字节写入，列地址偏移为 2。SPI2 使用 mode 0、1 MHz，无 MISO。禁用 DMA 时，每次 SPI 传输不超过 64 字节，每页 128 字节分两次发送；设置 `max_transfer_sz` 不能扩大非 DMA 的硬件 FIFO 上限。

GPIO46 是启动配置引脚；外接屏幕不得在芯片复位采样时强拉高，避免影响下载模式。若连接屏幕后无法进入烧录模式，先断开 RES 排查。引脚功能参考 [ESP32-S3 官方开发板说明](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html)。

显示内容（英文 5×7 字体，每 200 ms 刷新）：

- `IDLE`：开机后尚未启动板载脚本。
- `RUNNING`：板载脚本正在执行。
- `WAITING`：脚本正在等待指令指定的延时，不表示暂停。
- `STOPPED`：收到停止命令，或下载脚本前停止执行。
- `FINISHED`：有效板载脚本执行地址到达结尾；空脚本显示 `NO SCRIPT`。
- `TIME`：本次运行时间，停止／结束后保留，再次启动清零。
- `ADDR / END`：当前字节码地址及结束地址，十六进制；循环和跳转会改变 PC，因此这不是完成百分比或源代码行号。
- `WAIT`：剩余等待毫秒数，状态和位置约每 100 ms 采样。
- `USB`：TinyUSB 是否已枚举连接，不代表 Switch 已接受所有按键报告。

收到完整且被接受的 PC 按键／摇杆报告后，屏幕切换到 PC 活动页：

- `PC ACTIVE`：距最近一次控制报告不足 2 秒。
- `PC IDLE`：至少 2 秒没有新控制报告。PC 脚本延时、停止、通信中断均可能出现这个状态。
- `LAST`：距最近一次控制报告的毫秒数。
- `REPORTS`：收到并接受的控制报告数量，包含中立／松键报告；从开机或最近一次板载脚本启动后累计。
- `BTN / HAT`：最近接受的按键位图和方向帽值，十六进制。
- `L / R`：最近接受的左右摇杆 X/Y 值，十六进制。

握手、心跳、版本查询不计为 PC 活动。板载脚本启动时清除 PC 活动记录，优先显示板载脚本页；执行期间返回 BUSY 的 PC 控制报告不计数。PC 页显示的是最近收到的报告，不保证 USB 主机成功接收了对应 HID 报告。

不修改上位机或串口协议。现有协议未传输电脑端脚本的运行状态、名称或行号，因此 PC 活动不等于脚本运行状态，不能据此显示准确的开始／停止／完成。屏幕任务优先级低于脚本及通信任务，不在显示时持有解释器状态锁。初始化或传输 API 失败时仅记录日志，继续运行手柄功能。SPI 无应答，固件无法检测屏幕是否实际插入。

驱动命令参考 [SH1106 数据手册](https://www.displayfuture.com/Display/datasheet/controller/SH1106.pdf)。首次上板请依次验证：上电显示 IDLE、启动脚本、延时显示 WAITING、停止后计时保持、重启脚本计时归零、自然结束显示 FINISHED，以及插拔 USB 后状态变化。
